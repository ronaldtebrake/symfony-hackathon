### Native agent Code Mode over HTTP

The [Claude rehearsal](https://ronaldtebrake.github.io/symfony-hackathon/?client=claude#native-rehearsal) is a separate capture from 17 November, using Claude Code 2.1.326 and Sonnet 5.5. Its JavaScript executes in Claude; the unchanged Symfony app receives literal JSON. The original film and Hugging Face evidence remain separate.

To rehearse, connect Claude to the authenticated HTTP app from the quickstart. Start an **interactive terminal session** with `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude --model sonnet`; verify the native Code Mode startup banner. The feature is experimental and requires an eligible account and supported model; `claude -p` does not establish this proof. [Current requirements](https://code.claude.com/docs/en/code-mode).

Ask it to discover the article reader and read article 101 exactly once. After its answer, revoke permission with `demo:reader-access revoke`, without resetting the budget. In the same conversation, ask it to repeat the exact read once, then repeat its discovery query. The capture contains the exact prompts, all five generated JavaScript blocks, both client-discovery steps, four actual MCP calls and the model's unedited answers. Symfony's profiler shows no handler invocation for the denial and two consumed execution attempts.

The recorded session exposed only the rehearsal MCP server and the built-in REPL/ToolSearch tools. A loopback forwarding proxy captured the real HTTP bodies; completed profiler collectors were matched by exact request body. Its disposable app used separate credentials and grants, then was removed. Only the reviewed JSON export is published. This is an interoperability check, not a token comparison or a replacement for server authorization.

**Earlier two-way comparison (catalog only):** [Native Code Mode versus regular MCP](https://ronaldtebrake.github.io/symfony-hackathon/?client=claude-comparison#native-rehearsal) uses two new interactive sessions with identical prompts from [the capture](claude-http-comparison.json). Both use `--model claude-sonnet-5-5 --effort medium --tools REPL,ToolSearch --strict-mcp-config`, the same MCP allowlist and existing auto permission mode. Set `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=0` for regular MCP and `1` for native Code Mode. Start each with fresh application permissions and budget; revoke only between its two answers. Do not change prompts to favor either path. Both attempts are retained, including all discovery, answers, JSON calls and generated JavaScript. Both advertise the two catalog tools; this is not a full-tool versus catalog comparison.

Regular MCP used 44,131 main-conversation tokens and seven requests; native Code Mode used 73,251 and six. Both read the right article, denied the revoked call and hid its contract. The native follow-up combined two calls into one generated block, but its first request carried 11,238 input tokens versus 5,281 for regular MCP. This measures the full client mode, including its different runtime instructions, rather than just Symfony's tool schemas. The prompt contents were not captured, so we cannot attribute that extra input precisely.

Token accounting selects the last usage counters for each unique API message ID; repeated transcript content blocks must not be counted twice. Sum uncached input, cache-write input, cache-read input and output. Keep the cache categories visible: regular ran first, native second, sharing an account with potentially warm caches. These are provider counters, not a bill or a controlled cache-cost comparison. Unreported internal classifier/background usage is excluded. Correctness checks exact tool outcomes and binds the review of each unedited final answer to its hash; it is not a general agent reliability score. The comparison is separate from the film and historical audit benchmarks.

### Four-way Claude audit: full tools × JSON catalog × native Code Mode

The [four-way workbench](https://ronaldtebrake.github.io/symfony-hackathon/?client=claude-audit#native-rehearsal) compares two iterations, each containing four real interactive Claude Code 2.1.326 sessions. All use Sonnet 5.5 at medium effort, the same audit question, 48 published articles, 24 images and three approved Symfony AI readers. No model answer is repaired or discarded. The [capture](claude-audit-matrix.json) retains all eight attempts, including actual JSON calls, generated JavaScript, public answers, bounded Symfony traces and provider usage.

The latest iteration clarifies the ID parameters in the **shared reader contracts**: article IDs come from the listing; media IDs come from the returned articles' `image_id` values. A short article/media domain label makes the catalog entry discoverable to client-side search. No validation rule, permission, budget, fixture, model or question changed. All four latest answers are correct:

| MCP surface | Claude native Code Mode | Total tokens¹ | Model requests | Correct audit |
| --- | --- | ---: | ---: | --- |
| All 3 approved readers | Off | 54,067 | 5 | 10 / 10 findings |
| All 3 approved readers | On | 94,655 | 7 | 10 / 10 findings |
| Symfony's 2-tool JSON catalog | Off | 60,781 | 6 | 10 / 10 findings |
| Symfony's 2-tool JSON catalog | On | 143,647 | 9 | 10 / 10 findings |

Why the extra tokens? In regular mode, the catalog reduced first-request input only from 6,647 to 6,505 tokens, then required an extra discovery request. Subsequent requests include accumulated history. In native mode, the catalog also returned raw intermediate data to the model and hit a string/object runtime error before recovering. The direct/native run hit two such errors and repeated two reads. Both HTTP surfaces already return structured JSON plus its text representation; Claude's runtime exposed text in these calls. Output schemas and actual client handling deserve a separate interoperability investigation, not an untested promise of a fix.

The original iteration remains selectable, with its failed catalog-only audit and unchanged evidence:

| MCP surface | Claude native Code Mode | Total tokens¹ | Model requests | Correct audit |
| --- | --- | ---: | ---: | --- |
| All 3 approved readers | Off | 53,749 | 5 | 10 / 10 findings |
| All 3 approved readers | On | 49,432 | 4 | 10 / 10 findings |
| Symfony's 2-tool JSON catalog | Off | 54,939 | 6 | Incomplete |
| Symfony's 2-tool JSON catalog | On | 91,145 | 7 | 10 / 10 findings |

The regular catalog run guessed media IDs beyond the permitted 1–24 range. Two batches stopped on a denied call. Earlier calls ran but their partial results were withheld; Claude stopped without a JSON audit. Its 54,939 tokens remain counted. The native catalog run initially searched the client runtime for “article” and found nothing, then discovered the catalog and completed the audit. These extra steps remain visible too.

The catalog did not establish a token advantage in either iteration. Full-tool native execution used the fewest tokens in the original sample; regular direct calls used the fewest in the rerun. Catalogs control which schemas are exposed; native Code Mode can compute over returned data. Combining the two adds discovery steps, so their benefits do not automatically add up. Three approved tools cannot test the separate large-catalog scaling claim. Compare configurations **within an iteration**; do not pool contract versions or select only the cheapest attempts.

¹ Includes uncached input, cache-write input, cache-read input and output, once per unique API response. This is not a bill. Each iteration predeclared the order full/regular → catalog/native → catalog/regular → full/native; cache was not controlled. One attempt per cell per contract version does not establish average cost or reliability. Internal background/classifier usage is not reported here. The workbench shows first-request input separately and the measured usage of every subsequent request, without inventing a schema-versus-data token split.

Both surfaces use the same `ApprovedToolbox`, `ToolBroker`, `BatchSession` and persistent identity-bound state. The full surface advertises all three contracts; the catalog advertises `search_tools` and `execute_tools`, then discovers those identical contracts. Each starts with 20 execution submissions and 20 underlying calls; failures consume budget. This separate benchmark does not change the recording app's limits or permissions. Draft denial, revocation, hidden discovery and budget persistence are integration checks; they are not additional prompts in this fixed-permission audit.

```sh
php scripts/claude-audit-host.php direct var/demo/new-audit/direct-regular
# For the catalog arms, use "catalog" and a separate new capture directory.
```

The host creates `mcp.json` and a private `private.json`; supply its token to Claude as `SYMFONY_REHEARSAL_TOKEN` without printing or committing it. In an empty trusted working directory, use the same CLI flags for all four arms:

```sh
  --model claude-sonnet-5-5 --effort medium \
  --strict-mcp-config --mcp-config /absolute/capture/path/mcp.json \

```

Change only the native flag to `1` for the two native arms; the host sets `alwaysLoad: true` in every MCP config. Keep the same permission mode. Paste `protocol.question` from the retained capture exactly, with no expected findings or corrective hints. Native mode is interactive: do not substitute a scripted model response or a `claude -p` run. Create the host capture directory's `stop` file when finished to remove its disposable application and token. The export script selects public fields from the real transcripts; offline tests verify answers against the fixture and bind calls to their client event IDs. ### Reproduce the field selection measurement

Run `php scripts/field-selection-proof.php` from the project root. A local PHP MCP SDK client audits the same published articles over Symfony HTTP in three configurations. The original catalog returns full rows. The enhanced catalog accepts optional field selection and is measured twice, with full rows and selected fields. Compare the latter two to see the effect of selecting fields. The original catalog shows how much the additional contract costs to discover.

For a media read, `{"ids":[7],"fields":["id","alt"]}` asks the server to return only `id` and `alt` in each row. The reader authorizes and reads the records as usual. The client can join the smaller response to its article rows in JavaScript.

The report counts serialized MCP request and response bodies, including session setup, discovery and execution. Totals include both the structured results and their JSON text representation. HTTP headers and network framing are excluded. Compare the finding hashes and handler counts alongside the byte totals. The eight interactive Claude sessions above measure provider tokens on earlier contracts. This fixed audit makes zero model requests.

The SDK measured **55,238 bytes with full rows and 39,206 with selected fields**, a 29.0% reduction including discovery. The original catalog used 52,722 bytes. Enabling selection adds 2,516 discovery bytes in this fixture. All paths made ten authorized handler calls, produced the same ten findings, and denied the draft and post-revocation probes before handler execution. The readers load the same records. The measured saving occurs when sending data from Symfony to the client.

Two additional fresh Claude native Code Mode sessions received the original audit question. The baseline used 173,097 provider tokens in 12 requests. When offered field selection, Claude used it on six of ten underlying reads, asking for article IDs, descriptions and image IDs, then just media IDs and alt text. It used 167,618 tokens in 11 requests. Both responses matched the fixture. The latter script reconstructed titles from a repeating pattern in the listings, which would be brittle on other data. The fixed SDK audit joins real titles from the returned rows. The model sessions differed in retries and cache usage, so the observed 3.2% token difference gives no causal estimate. Inspect the [live pair](claude-field-selection.json) or the [workbench](https://ronaldtebrake.github.io/symfony-hackathon/?client=claude-fields#native-rehearsal).

To repeat the live comparison, use the interactive audit procedure above with native mode on for both sessions. Run the `catalog` host first and `catalog-fields` second, each with fresh state. The pair's `protocol` is the predeclared `iteration.json` and specifies the unmodified question. Save these arms in `baseline` and `offered` directories. Export to a new file with `python3 scripts/export-claude-audit.py --field-selection /absolute/capture-directory --output /path/to/new-pair.json`.
