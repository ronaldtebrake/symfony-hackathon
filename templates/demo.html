These fixed probes use a 2-second wall-clock budget and 128 MiB per execution. Elapsed time includes container setup and cleanup; the watchdog starts at attachment. Each container’s absence is checked with Docker after execution. Passing these probes is evidence of specific controls, not a security audit.

        

      


      
The trust boundary
Useful access.
Explicit limits.
The generated program is untrusted. The host owns tool permissions and execution limits.
01gVisor required
Native PHP in a userspace kernel sandbox. No ordinary-container fallback.
02No guest network
No host mounts, credentials or Docker socket. A read-only root filesystem.
03Bounded execution
15 seconds, 128 MiB, 30 tool calls per attempt. At most two attempts per session.
04Broker authorization
Local allowlist and argument validation on every call. Upstream hints grant no permissions.

      
This is a verified development proof. Production deployment still needs independent security review, admission limits and operational supervision. The web page only reads proof reports. Conversations stay in Codex; execution starts through MCP or the operator CLI.
