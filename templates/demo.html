Adopt it in your Symfony application

Your tools. One small integration.

Keep your existing Symfony AI tool services. Register the approved names, supply a host-owned authorization policy and expose Code Mode to any MCP client.

01

Install the bundle

The hackathon packages are currently installed from this repository with Composer path repositories. The independent example owns its dependencies.

composer install --working-dir=examples/symfony
php examples/symfony/bin/console code-mode:doctor
Open the minimal Symfony application ↗
02

Approve tools and set a policy

Symfony AI provides the tool schemas. The policy checks the caller and arguments on every invocation, including calls inside loops. Tool descriptions never grant access.

code_mode:
    ai_toolbox: app.toolbox
    ai_tools: ['publication_read']
    ai_authorization: Adoption\ReadPolicy
    identity_provider: Adoption\LocalReader

Example configuration; use service IDs and tool names from your app. Read the complete working configuration ↗

03

Connect your agent

Configure a STDIO MCP server with the project as its working directory. The host owns the identity, catalog and budgets.

php bin/console code-mode:serve --no-debug

For this repository’s editorial audit, use code-mode:mcp. For native Symfony AI, inject CodeModeToolbox into your agent.

Check prerequisites before executing generated PHP.

The secure profile requires a pinned runner image and Docker with gVisor. code-mode:doctor reports what is ready locally. The explicitly opt-in local_unsafe profile is for trusted development code; it is not isolation for untrusted PHP.

    The trust boundary
    Useful access.
    Explicit limits.
    The generated program is untrusted. The host owns tool permissions and execution limits.
    01gVisor required
    Native PHP in a userspace kernel sandbox. No ordinary-container fallback.
    02No guest network
    No host mounts, credentials or Docker socket. A read-only root filesystem.
    03Bounded execution
    15 seconds, 128 MiB, 30 tool calls per attempt. At most two attempts per session.
    04Broker authorization
    Local allowlist and argument validation on every call. Upstream hints grant no permissions.
    
      
    This is a verified development proof. Production deployment still needs independent security review, admission limits and operational supervision. The web page only reads proof reports.
